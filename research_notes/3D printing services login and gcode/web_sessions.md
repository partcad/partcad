# Driving print services' internal web APIs with the user's own signed-in session (Nov 2026)

Scope: Xometry (US, EU), Protolabs / ProDesk, Protolabs Network (Hubs), Fictiv, JLC3DP, PCBWay, Craftcloud (web app vs public API), Treatstock (web app), Weerg, SendCutSend, Shapeways (web app). Researched 2026-11-22.

Method note: besides published sources, this researcher sent **unauthenticated** GET requests (curl, Chrome-like User-Agent, from a US cloud/datacenter IP behind a proxy) to each service's public pages and read the response headers and the public HTML/JS bundles the browser downloads before login. These requests show which CDN or bot-protection vendor answers and which API hosts the web app's code names. They are labelled "Observed 2026-11-22". No account was created, and no request needed authentication. A datacenter IP with curl's TLS fingerprint is roughly what a PartCAD plugin running in a container on another machine looks like to these sites, so the observations bear directly on that deployment. They do not show how a residential IP with a real browser fingerprint would be treated.

## 1. How each service's web instant quote works technically (API shape, credential type, CSRF, STEP)

### Takeaway
Every service in scope runs its instant quote as a browser single-page app or server-rendered app on its own JSON/GraphQL backend. Most are cookie-session based: Xometry US and EU (GraphQL with `credentials: include`), Fictiv (GraphQL with credentials), SendCutSend (Rails, CSRF token), Treatstock (PHP session plus Yii-style CSRF cookie), PCBWay (ASP.NET cross-subdomain session) and Protolabs (an OIDC identity server plus an ASP.NET session). None is documented, so endpoint names and lifetimes below come from public bundles and are unverified beyond what the code names. Craftcloud is the exception: it has a public, keyless REST API, so a session is unnecessary.

### Cited Findings
**Xometry (US)**
- The quoting app (`www.xometry.com/quoting/...`) loads an `env.js` naming `AUTH_ORIGIN: 'https://auth.xometry.com'`, `GRAPHQL_ENDPOINT: '/api/graphql/'`, `GRAPHQL_ORIGIN: 'https://www.xometry.com'` and `API_ORIGIN: 'https://api.xometry.com'`. Observed 2026-11-22 in the [quoting app env.js](https://www.xometry.com/quoting/4ffc0548bf742af2bbe5f05ac43a66a7d972a7e9/env.js), reached from [get.xometry.com](https://get.xometry.com/), which redirects to `/quoting/home/`.
- The 2.4 MB instant-quote bundle makes its GraphQL calls with `credentials:"include"` (20 occurrences), meaning a cookie session, not a bearer token in storage. It names operations matching an upload → quote → purchase-order flow: `CreatePartQuoteUploadBatch`, `AddPartQuoteUploadFiles`, `FinalizePartQuoteUpload`, `CreateQuoteFromPartRevisions`, `CreatePurchaseOrderWithQuotes`, `AttachQuotePurchaseOrder`. File upload goes through `uploadUrl` values (presigned upload). REST paths such as `/api/requirements-service/2/menus` sit beside the GraphQL calls. Observed 2026-11-22 in the [instant-quote-app bundle](https://www.xometry.com/quoting/4ffc0548bf742af2bbe5f05ac43a66a7d972a7e9/resources/instant-quote-app.be0edaa6cf1e9b5d0443.mjs).
- The same bundle queries a per-user flag `me { ... on User { partsApiEnabled } }` and logs `"parts-api buyer client query failed"`. That suggests an internal "parts API" service gated per buyer. Nothing public documents it (meaning **unverified**). Same source.
- The bundle names `StaffProxy` variants of mutations (`CreateQuoteFromPartRevisionsAsStaffProxy`), so staff can act on behalf of a buyer. Same source.
- An empty GET to `https://www.xometry.com/api/graphql/` returned HTTP 400 with `access-control-allow-credentials: true`. Observed 2026-11-22.
- Xometry's terms say quotes are reviewed before an order is finalized, and "No contract to manufacture any Part exists until Xometry acknowledges Your acceptance of its Quote" — [Xometry Service Agreement](https://www.xometry.com/service-agreement/).

**Xometry (Europe)**
- `get.xometry.eu` is a separate SPA (S3/CloudFront). Its bundle names `https://api.xometry.eu`, uses GraphQL and sets `withCredentials` (cookies). Observed 2026-11-22 at [get.xometry.eu](https://get.xometry.eu/) and its `/assets/index-*.js`.
- Xometry Europe's terms say the company "shall be bound by this quote for seven (7) calendar days" (search snippet) — [Xometry EU terms](https://xometry.eu/en/?p=667).

**Protolabs, including ProDesk**

Observed 2026-11-22.
- Supergood (an unofficial-API vendor) says: "Protolabs publishes no public API and no developer portal." Quoting, DFM, orders and tracking "stay inside the ProDesk web experience" — [Supergood report card: Protolabs](https://supergood.ai/api-report-card/protolabs) (verified Nov 2026).

**Protolabs Network (Hubs)**
- `www.hubs.com` is served from S3/CloudFront. `app.hubs.com` returned 502 through this researcher's proxy, so its API could not be inspected. Observed 2026-11-22.

**Fictiv**
- The `app.fictiv.com` HTML embeds `"GRAPHQL_API_BASE":"https://prod-graphql.fictiv.com/api/graphql"` and `"GRAPHQL_API_REST_BASE":"https://prod-graphql.fictiv.com/api/rest"`. - One open-source project orders at JLCPCB and its sister services (including JLC3DP) by driving the user's **own signed-in browser** with the Claude in Chrome extension, not by replaying a cookie from a server. "The agent never pays. It prepares each order up to the cart or the payment page." — [pedro-setera/ee-skills-claude-pub README](https://raw.githubusercontent.com/pedro-setera/ee-skills-claude-pub/main/README.md).

**PCBWay**
- The 3D-printing page is server-rendered ASP.NET on IIS behind CloudFront. Login state is synchronised across subdomains by scripts at `login.pcbway.com/GetSessionP.aspx`, `login.pcbway.com/RemoveSessionP.aspx` and `member.pcbway.com/SetCookie.aspx` — a classic cookie session. Observed 2026-11-22 at the [PCBWay 3D printing page](https://www.pcbway.com/rapid-prototyping/3d-printing/).
- PCBWay's official KiCad plugin uploads production files and offers "Save to Cart" — [PCBWay-Plug-in-for-Kicad](https://raw.githubusercontent.com/pcbway/PCBWay-Plug-in-for-Kicad/main/README.md).

**Craftcloud (web app vs public API)**
- `https://api.craftcloud3d.com/api-docs.json` returned 200 JSON, while `craftcloud3d.com` returned a Cloudflare managed challenge (`cf-mitigated: challenge`, 403). Observed 2026-11-22.
- PartCAD's earlier report found the public v5 API quotes and orders without any key, ending in a Stripe Checkout URL — [PartCAD report](file:///home/user/partcad/reports/3D%20printing%20service%20APIs%20for%20PartCAD.md), citing [Craftcloud spec](https://api.craftcloud3d.com/api-docs.json).
- All3DP's own Ruby gem sends 3D files to "Craftcloud, All3DP's 3D Printing Price Comparison Service API" — [cults/all3dp on GitHub](https://github.com/cults/all3dp).

**Treatstock (web app)**
- The upload page is served by nginx (PHP). It sets `PHPFRONTSESSID` (HttpOnly, no expiry, so the cookie lasts the browser session) and `_frontendCSRF` (HttpOnly, Max-Age 2591999 ≈ 30 days; the name matches the Yii framework's CSRF cookie convention). It loads reCAPTCHA v3 (`recaptcha.execute`). Observed 2026-11-22 at [treatstock.com/upload](https://www.treatstock.com/upload).
- Treatstock has an official API repository (`Treatstock/apiv2`, last updated 2022) — [GitHub](https://github.com/Treatstock/apiv2).

**Weerg**
- The quotation tool is at `www.weerg.com/en/global/quotation-tool/config`, a HubSpot-CMS page using jQuery, behind Cloudflare (sets `__cf_bm`), with reCAPTCHA. Its HTML names no separate API host. Observed 2026-11-22.
- Weerg's `llms.txt` (revised 2026-09-24) tells agents: "Prices, promotions, availability, quantities, production times and dispatch dates are dynamic. Do not derive them from static content: invite the user to upload their file to the Weerg quoting tool." — [weerg.com/llms.txt](https://www.weerg.com/llms.txt).

**SendCutSend**
- `app.sendcutsend.com` is a Rails app on Heroku behind Cloudflare. Its HTML carries `csrf-param` `authenticity_token` with a `csrf-token` meta tag, a reCAPTCHA v3 script (`recaptcha/api.js?render=...`) and Braintree hosted fields and vault. It names `drawing_api_host: https://drawing.sendcutsend.com` and `ship_estimate_url: https://cache.sendcutsend.com/orders/ship_estimate`. Observed 2026-11-22 at [app.sendcutsend.com/customer](https://app.sendcutsend.com/customer).
- Supergood: "SendCutSend has no public API and no developer portal." `api.sendcutsend.com` "returns only a route not found error". The only developer-facing artifact is an Autodesk Fusion plugin. "Credentials exist only for customer logins on the app.sendcutsend.com portal." — [Supergood report card: SendCutSend](https://supergood.ai/api-report-card/sendcutsend) (dateModified 2026-11-20).
- A community workaround for the Fusion add-in shows that the add-in logs in through an OAuth-style "authorize URL" with **PKCE** and stores the resulting tokens — [evtrapper/Fusion360-SendcutSend-Manual-Module README](https://raw.githubusercontent.com/evtrapper/Fusion360-SendcutSend-Manual-Module/main/README.md).
- SendCutSend validation tooling accepts "DXF and STEP files" — [earthtojake/sendcutsend-skill](https://github.com/earthtojake/sendcutsend-skill).

**Shapeways (web app)**
- `www.shapeways.com`, including `robots.txt`, returned Cloudflare 403 to this researcher. The official API hosts `developers.shapeways.com` and `api.shapeways.com` returned 200. Observed 2026-11-22.
- Official Shapeways API clients (OAuth) remain on GitHub, last updated 2023–2024 — [Shapeways/shapeways-api](https://github.com/Shapeways/shapeways-api); [Shapeways/python-shapeways](https://github.com/Shapeways/python-shapeways).

**Public projects that drive these internal APIs**
- A GitHub repository search (names and descriptions only, not code) for each service found no public client or browser automation calling Xometry's, Fictiv's, Protolabs', Hubs', Weerg's or SendCutSend's internal quote APIs. The hits were unrelated, official, or partner-API wrappers such as `singlebarrellabs/pcbway-mcp-server`, which wraps the PCBWay **Partner** API. Observed 2026-11-22 via `gh search repos`.
- An Apify "Xometry Scraper" exists for public capabilities, materials and case studies, not for authenticated quoting — [Apify](https://apify.com/lentic_clockss/xometry-scraper).

### Inferences
- A PartCAD plugin for Xometry would replay the `auth.xometry.com`-issued cookies against `www.xometry.com/api/graphql/`, run the upload-batch → finalize → create-quote mutations, and poll for prices. "Order" would be `CreatePurchaseOrderWithQuotes` or the checkout path. The exact cookie names, the payloads and whether payment can be completed without a browser are unknown.
- Fictiv's split between an app host and a GraphQL host makes it the cleanest technical target (a single GraphQL endpoint). But its credentialed CORS and 401 show the session must travel as cookies scoped to `.fictiv.com`, or possibly a header the bundle sets (not confirmed).
- Rails CSRF (SendCutSend) and Yii CSRF (Treatstock) mean a Python client must first GET a page, parse the token and send it back with each POST. That is doable but couples the plugin to HTML structure.
- Any action guarded by reCAPTCHA v3 (present on SendCutSend's app, Treatstock's upload, Weerg's tool and Protolabs' buildit) needs a token minted by Google's script in a real browser. A Python process cannot produce one. Which actions are guarded (login only, upload, or checkout) is unknown.
- STEP: Xometry's bundle references `.step`, and every service's public pages advertise STEP upload. That makes STEP the natural format for a session-driven plugin, unlike the STL-only public APIs (Slant 3D, Craftcloud examples).
- Craftcloud needs no session path. Its public API is reachable from a datacenter IP while its web front is challenged, so a plugin should never touch `craftcloud3d.com` itself.

### Gaps
- Session lifetimes, cookie names, refresh mechanisms and idle timeouts were not observable without signing in, for every service. ASP.NET's 20-minute default session timeout for `myrapid` is assumed rather than verified.
- Not inspected: Hubs (`app.hubs.com` unreachable through the proxy), the ProDesk app's API host (only the `buildit`/`identity` hosts were seen), JLC3DP's quote backend (the page's own XHR endpoints were not found in static HTML), and PCBWay's 3D-printing quote form endpoints.
- No public reverse-engineering write-up was found for any of these services' quote flows. Supergood, Apify and RapidAPI were checked by search only, and only Supergood had report cards.

## 2. Bot protection: how likely are server-side requests with a captured cookie to be blocked?

### Takeaway
The services split into three tiers. **Xometry US** (DataDome plus a Vercel challenge plus Cloudflare), **Xometry EU, Shapeways and Craftcloud's web front** (Cloudflare blocking or challenging a datacenter client outright) are poor candidates for server-side replay. **Protolabs, Fictiv's marketing site, Weerg and SendCutSend** run Cloudflare with Bot Management cookies, plus reCAPTCHA v3 in places. **PCBWay, Treatstock and JLC** showed no bot-management vendor on the pages checked. Cloudflare documents that its clearance cookie is tied to the device it was issued to, and third-party sources say DataDome's cookie is tied to IP, User-Agent and fingerprint. So a cookie captured in the user's browser and replayed from a container on another machine will often be re-challenged, and the plugin cannot answer a challenge.

### Cited Findings
- **Xometry US**: `https://www.xometry.com/` returned **HTTP 429** with `x-datadome: protected`, a `datadome` cookie with `Max-Age=31536000`, `x-vercel-mitigated: challenge` and `server: cloudflare`. `/quoting/home/` returned 200 but still carried `x-datadome: protected`, and returned 200 with a `python-requests` User-Agent too. Observed 2026-11-22 (twice, same result).
- **Xometry EU**: `https://xometry.eu/` returned **403** from Cloudflare with a `__cf_bm` cookie. WebFetch of its terms page also got 403. Observed 2026-11-22.
- **Shapeways**: `www.shapeways.com`, including `/robots.txt`, returned **403** from Cloudflare. WebFetch of the terms URL failed as well. Observed 2026-11-22.
- **Craftcloud**: the web front returned 403 with `cf-mitigated: challenge` (a Cloudflare managed challenge), while `api.craftcloud3d.com/api-docs.json` returned 200. Observed 2026-11-22.
- **Fictiv, Weerg, SendCutSend, get.protolabs.com**: Cloudflare set `__cf_bm` (and `_cfuvid`). `www.protolabs.com` and `buildit.protolabs.com` are on Cloudflare. Fictiv's GraphQL host is plain nginx (401). Observed 2026-11-22.
- **JLC3DP / JLCPCB**: Akamai CDN headers (`x-akamai-transformed`, `akamai-grn`). No `_abck`/`bm_sz` Bot Manager cookie appeared on the homepage or the quote page. Login is on `passport.jlc.com` behind `volc-dcdn`. Observed 2026-11-22.
- **PCBWay**: CloudFront plus IIS/ASP.NET, with no bot-vendor header or cookie. **Treatstock**: nginx, with no CDN bot vendor, but reCAPTCHA v3 on upload. Observed 2026-11-22.
- Cloudflare's `__cf_bm` "contains information related to the calculation of Cloudflare's proprietary bot score" and "expires after 30 minutes of continuous inactivity" — [Cloudflare cookies](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/cloudflare-cookies/).
- Cloudflare's `cf_clearance` "proves to Cloudflare that the visitor is a verified human". "The cookie is securely tied to the specific visitor and device it was issued to, preventing reuse across machines." It stays valid for the zone's Challenge Passage, and with Precursor "the visitor may be re-challenged, even if the cookie has not expired" — [Cloudflare Challenges: clearance](https://developers.cloudflare.com/cloudflare-challenges/concepts/clearance/).
- Third-party guidance holds that the clearance is bound to IP, User-Agent and TLS/JA3 fingerprint — [DEV Community](https://dev.to/bshahin/cloudflare-cfclearance-why-it-expires-and-how-to-stop-the-re-challenge-loop-do9); the `cf_clearance` PyPI project likewise says to use the same IP and UA — [PyPI](https://pypi.org/project/cf_clearance) (secondary; Cloudflare's own page says only "visitor and device").
- DataDome: third-party sources say its cookie is tied to the IP, User-Agent and fingerprint that produced it, that copying it into another session does not work, and that the score is recalculated on every request — [Browserless](https://www.browserless.io/blog/datadome-bypass); [Scrappey](https://scrappey.com/qa/web-automation/how-datadome-detects-bots); [DEV Community](https://dev.to/bshahin/what-datadome-actually-checks-and-why-your-cloudflare-playbook-doesnt-transfer-24b5) (vendor-adjacent sources; no DataDome primary doc retrieved).

### Inferences
- For PartCAD's "plugin in a container on another machine" mode, Xometry is the most likely to fail. DataDome scores every request and its cookie is reportedly IP- and fingerprint-bound, and a `requests`/`httpx` TLS fingerprint differs from Chrome's even on the same machine. Expect intermittent 403 or 429 responses carrying a CAPTCHA page, which the plugin cannot solve and which the user would have to clear in the browser profile and re-capture.
- Cloudflare-fronted apps (Protolabs, Weerg, SendCutSend, Fictiv's marketing hosts) may let API calls through on a low bot score without a challenge. If a challenge does fire, the `cf_clearance` the extension captured will not transfer across machines (per Cloudflare's own docs). Same-machine replay with a matching UA is more likely to work, but the TLS fingerprint still differs.
- PCBWay, Treatstock and JLC (as observed) are the least protected at the network layer. Their remaining barriers are CSRF tokens and reCAPTCHA v3 on specific actions.
- Mitigations within PartCAD's rules (no CAPTCHA solving): run the plugin on the user's own machine, send the User-Agent captured with the cookie, keep request rates human-like, and treat any challenge response as "re-login needed" rather than retrying. Each of these reduces, but does not remove, the chance of a block.

### Gaps
- Whether DataDome guards `/api/graphql/` with a captured session cookie, as opposed to the anonymous HTML, was not tested (it would require authentication).
- Akamai Bot Manager may be enabled on JLC's login or cart endpoints even though no cookie appeared on public pages. Not verifiable without signing in.
- No primary DataDome documentation on cookie binding was retrieved.

## 3. Terms of service clauses on automated access, scraping, bots and third-party tools

### Takeaway
Xometry, Fictiv, Protolabs, Protolabs Network and Treatstock explicitly forbid automated software, robots or scripts. Xometry and Fictiv also forbid reverse-engineering their **pricing algorithms**, which is what systematically calling a quote endpoint can look like. PCBWay forbids "scraping tools, automated abuse" that harm the site. SendCutSend forbids exploiting "access to the Service" without written permission. JLC's and Weerg's general terms have no explicit bot clause but reserve broad suspension rights. Nearly all forbid sharing the account or password. Craftcloud's, Shapeways' and Xometry EU's terms could not be retrieved (Cloudflare 403).

### Cited Findings
- **Xometry (US) Service Agreement, Last Updated July 28, 2026**: "You shall not or permit any third party to: 7.1.1 reverse engineer, disassemble or decompile the Website, the pricing and matching algorithms of Xometry, or Xometry's geometry parsing engine; 7.1.2 use any manual or automated software devices or other processes (including but not limited to spiders, robots, scrapers, crawlers, avatars, data mining tools or the like) to "scrape" or download data from any web pages contained in the Website". It adds: "In the event You attempt to reverse engineer such pricing and matching algorithms … Your right to use the Website and Service shall immediately cease". Also: "You may not share Your Account or password with anyone, and You agree to … (b) exit from Your Account at the end of each session." — [Xometry Service Agreement](https://www.xometry.com/service-agreement/).
- **Fictiv Terms**: "(b) use or attempt to use any manual or automated software devices or other processes (including but not limited to spiders, robots, scrapers, crawlers, avatars, data mining tools or the like) to "scrape" or download data from any web pages contained in the Site or use another user's account without authorization from that user and Fictiv; … (d) reverse engineer … the pricing and matching algorithms of Fictiv, or Fictiv's geometry parsing engine; … (i) … bypass or circumvent measures employed to prevent or limit access to any part of our Services; (j) use any data mining, robots or similar data gathering or extraction methods …; (m) bypass or ignore instructions contained in our robots.txt file". ### Inferences
- A PartCAD session plugin would breach the plain wording of the Xometry (§7.1.2), Fictiv ((b), (i), (j)), Protolabs, Hubs and Treatstock terms. The last three cap automation at "more communication than a natural person could reasonably produce", which a low-rate, user-initiated quote arguably stays under. Xometry's and Fictiv's clauses are not rate-qualified.
- Xometry's and Fictiv's "pricing algorithm" reverse-engineering clauses are the sharpest risk. A tool that submits parts programmatically and records prices is exactly what those clauses aim at, and Xometry's remedy is immediate loss of access.
- "Do not share your password" clauses are not obviously breached when the user captures their **own** session for their **own** process. But a plugin running "in a container on another machine" operated by someone else would arguably put the session in a third party's hands.
- SendCutSend, JLC, PCBWay and Weerg have the weakest textual prohibitions, so a ban there would rest on discretionary termination rather than an express clause.

### Gaps
- Craftcloud's, Shapeways' and Xometry EU's current terms were not retrievable (Cloudflare 403 to both curl and WebFetch; the Wayback Machine was not reachable from this environment).
- A JLC3DP-specific user agreement (beyond the JLCPCB T&C its help centre links to) was not found.
- Weerg's sales conditions, as opposed to its conditions of use, were not checked.

## 4. Legal background: a user automating their own account (US and EU)

### Takeaway
In the US, after *Van Buren* (2021) and *hiQ* (2022), a user reaching their **own** account with their own credentials is unlikely to violate the CFAA on a terms breach alone. That changes once the site revokes permission (a cease-and-desist, a ban or a technical block). *Facebook v. Power Ventures* is the on-point precedent for a third-party tool using users' own credentials. Contract liability is the live risk: logged-in use means the user accepted the terms, and *hiQ* (Nov 2022) enforced an anti-scraping clause. *Meta v. Bright Data* (2024) turned precisely on the scraper being **logged out**. In the EU, *Ryanair v PR Aviation* (CJEU 2015) lets a site enforce anti-scraping terms by contract where no database right applies. The EU Data Act is framed around connected products, and no evidence was found that it gives a right to automate a web shop. This is a summary, not legal advice.

### Cited Findings
- **Van Buren v. United States (2021)**: the Supreme Court read "exceeds authorized access" as a gates-up-or-down inquiry into which parts of a system a person may enter, not into the purposes behind otherwise-permitted access. Footnote 8 left open whether the limits must be technological or may also be "contained in contracts or policies" — [Supreme Court opinion, No. 19-783](https://www.supremecourt.gov/opinions/20pdf/19-783_k53l.pdf). This summary is from the researcher's knowledge of the opinion; the PDF was not fetched in this session.
- **Facebook v. Power Ventures (9th Cir. 2016)**: Power ran a service to which users gave their own Facebook credentials. The court held Power violated the CFAA and California Penal Code § 502 only after it received Facebook's cease-and-desist letter and kept accessing Facebook's computers. That letter "superseded any permission attributable to any Facebook user", and a terms-of-use violation alone does not support CFAA liability — [Fenwick](https://www.fenwick.com/insights/publications/the-ninth-circuit-holds-that-accessing-a-website-after-receiving-a-cease-desist-letter-is-a-violation-of-the-computer-fraud-and-abuse-act); [Justia opinion](https://law.justia.com/cases/federal/appellate-courts/ca9/13-17102/13-17102-2016-07-12.html); [Mintz](https://www.mintz.com/insights-center/viewpoints/2826/2016-07-facebook-v-vachani-user-authorization-can-be-revoked).
- **hiQ v. LinkedIn**: the Ninth Circuit held that violating a public website's user agreement alone does not trigger CFAA "without authorization" liability. In November 2022 the district court nonetheless granted LinkedIn summary judgment on **breach of contract**, holding the user agreement's bans on scraping and fake profiles enforceable and not unconscionable. A December 2022 consent judgment brought a $500,000 judgment (covering contract, CFAA and California § 502 claims) and a permanent injunction requiring hiQ to stop scraping and delete its code and data — [Proskauer, Nov 2022](https://newmedialaw.proskauer.com/2022/11/11/court-finds-hiq-breached-linkedins-terms-prohibiting-scraping-but-in-mixed-ruling-declines-to-grant-summary-judgment-to-either-party-as-to-certain-key-issues/); [Proskauer, Dec 2022](https://newmedialaw.proskauer.com/2022/12/08/hiq-and-linkedin-reach-proposed-settlement-in-landmark-scraping-case/); [Morgan Lewis](https://www.morganlewis.com/blogs/sourcingatmorganlewis/2022/12/linkedin-v-hiq-landmark-data-scraping-suit-provides-guidance-to-data-scrapers-and-web-operators).
- **Meta v. Bright Data (N.D. Cal., 23 Jan 2024)**: Judge Chen read Facebook's and Instagram's terms to prohibit **logged-in** scraping, not logged-off scraping. Bright Data was a logged-out "visitor", not a "user". Commentators note that the decision does not decide logged-in scraping. Meta dropped the case in February 2024 — [Farella Braun + Martel](https://www.fbm.com/post/102kqw7/); [TechCrunch](https://techcrunch.com/2024/02/26/meta-drops-lawsuit-against-web-scraping-firm-bright-data-that-sold-millions-of-instagram-records/); [Eric Goldman blog](https://blog.ericgoldman.org/?p=26009).
- **Ryanair v. Booking.com (D. Del.)**: in July 2024 a jury found Booking.com liable under the CFAA for (indirectly) accessing the logged-in **myRyanair** area to sell tickets. On 22 January 2025 the court granted judgment as a matter of law for Booking.com because Ryanair failed to prove the statutory $5,000 loss — [Holland & Knight](https://hklaw.com/en/insights/publications/2024/08/district-court-ruling-offers-insight-into-computer-fraud); [Cooley](https://www.cooley.com/news/coverage/2025/2025-01-22-cooley-secures-decisive-win-for-bookingcom-in-computer-fraud-and-abuse-act-case); [Eric Goldman blog](https://blog.ericgoldman.org/?p=27440).
- **EU: Ryanair v PR Aviation (C-30/14, CJEU, 15 Jan 2015)**: where a database is protected by neither copyright nor the sui generis right, the Database Directive's lawful-user rules do not apply. The maker may therefore restrict screen scraping by contract (the website terms), subject to national law — [Pinsent Masons Out-Law](https://www.pinsentmasons.com/out-law/news/website-operators-can-prohibit-screen-scraping-of-unprotected-data-via-terms-and-conditions-says-eu-court-in-ryanair-case); [Kluwer Copyright Blog](https://legalblogs.wolterskluwer.com/copyright-blog/ryanair-ltd-v-pr-aviation-bv-contracts-rights-and-users-in-a-low-cost-database-law/). One commentator argues such restrictions should also be assessed under competition law, which the CJEU did not address — same Kluwer source.
- **EU Data Act**: applicable since 12 September 2025. It covers data from **connected products** and **related services** (for example apps controlling those products), with access-by-design obligations for products placed on the market after 12 September 2026 — [European Commission, Data Act explained](https://digital-strategy.ec.europa.eu/en/factpages/data-act-explained); [Skadden](https://www.skadden.com/insights/publications/2025/06/eu-data-act). No source stated whether websites are excluded.
- **PSD2 analogy (EU banking)**: the EBA's final RTS treated screen scraping, in which the third party accesses the customer's online account "by pretending to be that customer", as non-compliant once banks offer a dedicated interface (from about 14 September 2019). Fallback and temporary national extensions softened this — [Pinsent Masons](https://www.pinsentmasons.com/out-law/news/psd2-screen-scraping-ban-confirmed-in-finalised-standards); [Pinsent Masons, FCA lifeline](https://www.pinsentmasons.com/out-law/news/psd2-fca-gives-temporary-lifeline-to-screen-scrapers).
- **CFPB § 1033 (US banking)**: the October 2024 final rule encourages moving from screen scraping to APIs and lets data providers block scraping once a compliant interface exists, without banning it outright. The rule is reported to be under rewrite, status unclear — [CFPB press release](https://www.consumerfinance.gov/about-us/newsroom/cfpb-finalizes-personal-financial-data-rights-rule-to-boost-competition-protect-privacy-and-give-families-more-choice-in-financial-services); [American Banker](https://www.americanbanker.com/news/on-the-day-of-a-would-be-deadline-open-banking-is-in-flux).

### Inferences
- For a PartCAD user automating their own account at a low rate, criminal or civil CFAA exposure in the US looks low **until** the service revokes access. After a ban, a cease-and-desist letter or an IP block, *Power Ventures* makes continued automated access the risky act. A plugin should treat a 401/403 after a ban, or a notice, as final and not try to work around it.
- The more realistic US exposure is contract: account termination, cancelled orders, and in theory damages for breaching the terms (*hiQ*). PartCAD as the tool's author is one step removed. But *Power Ventures* and *Ryanair v. Booking* show providers pursuing the intermediary, not only the user.
- In the EU, a provider's anti-automation clause is enforceable as contract (*Ryanair v PR Aviation*) unless national law on unfair terms (B2C) intervenes. The Data Act appears to give no right to automate a manufacturing marketplace, since a quote engine is not a connected product's related service. GDPR access and portability rights cover the user's personal data, not a pricing engine.
- Banking shows where regulators land: credential-sharing screen scraping is tolerated only until a dedicated API exists, then phased out as a security risk. Manufacturing has no such mandate, so the vendor decides.

### Gaps
- No case law was found on automating one's **own** account at a manufacturing marketplace.
- National EU law (German UWG and BGH screen-scraping decisions, unfair-terms review of B2C anti-automation clauses) was not researched.
- The *Van Buren* opinion text was not fetched in this session. Its summary above relies on the researcher's knowledge, though the case citation and URL are standard.

## 5. API key vs captured web session as the credential for an open-source tool

### Takeaway
A captured session is worse than an API key on nearly every axis: stability, account risk, security scope, lifetime, 2FA and revocation, and maintainability. It is acceptable for PartCAD's existing model-site plugins (GrabCAD, Printables), where the worst case is a failed download. It is far riskier for a plugin that spends money and holds payment-capable sessions. Real-world histories (Home Assistant's MyQ integration, Bambu Lab's cloud, Discord's self-bot ban, PSD2's screen-scraping ban) show vendors breaking, blocking or forbidding such integrations, and open-source maintainers ending up in constant repair or under legal threat.

### Cited Findings
- **Stability, Home Assistant and MyQ**: Home Assistant removed its MyQ integration in release 2023.12 after Chamberlain kept blocking third-party access. The integration had been "in constant repair" (it broke, was fixed and broke again), Chamberlain called the usage "unauthorized", and Home Assistant said it "cannot pay a partnership fee" — [Home Assistant blog, 6 Nov 2023](https://home-assistant.io/blog/2023/11/06/removal-of-myq-integration/); [CEPro](https://www.cepro.com/news/chamberlain-group-blocks-third-party-integrations-for-myq-garage-door-controller).
- **Stability and legal threat, Bambu Lab (3D printing)**: in January 2025 Bambu Lab's "Authorization Control" firmware cut third-party slicers and Home Assistant off from printer control and steered them to Bambu Connect — [Bambu Lab blog](https://blog.bambulab.com/firmware-update-introducing-new-authorization-control-system-2); [Tom's Hardware](https://www.tomshardware.com/3d-printing/bambu-lab-security-update-will-remove-orcaslicers-access). In May 2026 the developer of the "OrcaSlicer-BambuLab" fork, which restored cloud printing without Bambu Connect, shut it down after legal threats. Bambu later said it "regret[ted] that our reference to Terms of Service, legal context and a potential C&D understandably came across as a legal threat" — [Tom's Hardware](https://www.tomshardware.com/3d-printing/developer-re-enables-3d-printer-features-that-bambu-lab-disabled-firm-promptly-threatens-legal-action-orcaslicer-bambulab-project-now-shuttered); [All3DP](https://all3dp.com/4/bambu-lab-took-down-an-orcaslicer-fork-and-handed-it-a-bigger-audience); [Notebookcheck](https://www.notebookcheck.net/Bambu-Lab-backtracks-after-SFC-accuses-company-of-AGPL-violations-and-legal-threats.1303904.0.html). A November 2026 report says Bambu's cloud rejected requests from third-party software sharing one client identifier, ha-bambulab among them (single source, **unverified**) — [Tutkit](https://www.tutkit.com/en/news/1081-bambu-lab-cloud-blocking-third-party-software).
- **Account risk, Discord**: "Automating normal user accounts (generally called "self-bots") outside of the OAuth2/bot API is forbidden, and can result in an account termination if found." — [Discord support](https://support.discord.com/hc/articles/115002192352).
- **Security scope**: SendCutSend's app vaults payment methods through Braintree (`vault-manager.min.js`), and Treatstock's upload page loads Braintree. So the same session that quotes can reach stored payment methods. Observed 2026-11-22 ([app.sendcutsend.com](https://app.sendcutsend.com/customer), [treatstock.com](https://www.treatstock.com/upload)). Xometry asks users to "exit from Your Account at the end of each session" — [Xometry Service Agreement](https://www.xometry.com/service-agreement/).
- **Scoped, revocable alternatives exist where vendors chose them**: JLCPCB API calls use "Signed API key credentials, app_id with access_key and secret_key" — [Supergood: JLCPCB](https://supergood.ai/api-report-card/jlcpcb). PCBWay's partner API uses "a single `api-key` header" — [pcbway-mcp-server README](https://raw.githubusercontent.com/singlebarrellabs/pcbway-mcp-server/main/README.md). SendCutSend's Fusion add-in uses an OAuth authorize flow with PKCE — [Fusion360-SendcutSend-Manual-Module README](https://raw.githubusercontent.com/evtrapper/Fusion360-SendcutSend-Manual-Module/main/README.md).
- **Lifetime**: Cloudflare's `__cf_bm` expires after 30 minutes of inactivity, and `cf_clearance` lasts the zone's Challenge Passage (default 30 minutes per Cloudflare-related sources) — [Cloudflare cookies](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/cloudflare-cookies/); [Cloudflare clearance](https://developers.cloudflare.com/cloudflare-challenges/concepts/clearance/). Treatstock's and Protolabs myRapid's session cookies carry no expiry, so they last only as long as the browser session (`PHPFRONTSESSID`, `ASP.NET_SessionId`). Observed 2026-11-22.
- **Analogy, banking**: the EU's PSD2 RTS treated credential-based screen scraping as a security problem to be replaced by dedicated interfaces — [Pinsent Masons](https://www.pinsentmasons.com/out-law/news/screen-scraping-ban-under-psd2-on-security-grounds-eba-confirms). The US CFPB rule encourages the same transition — [Proskauer](https://newmedialaw.proskauer.com/2024/11/04/cfpb-issues-final-open-banking-rule-governing-third-party-use-of-consumer-banking-information/).
- **Alternative pattern, in-browser agent**: the JLC ordering skills drive the user's own signed-in browser and stop at the cart or payment page, so no credential ever leaves the browser — [ee-skills-claude-pub README](https://raw.githubusercontent.com/pedro-setera/ee-skills-claude-pub/main/README.md).

### Inferences
| Axis | API key / OAuth token (where offered) | Captured web session (cookie or storage token) |
| --- | --- | --- |
| Stability | Versioned, documented contract | Internal API changes with every front-end deploy (Xometry's bundle path is a commit hash) |
| Account risk | Sanctioned use | Explicitly forbidden by Xometry, Fictiv, Protolabs, Hubs, Treatstock; bans are discretionary everywhere |
| Security scope | Often scoped; can be limited to quoting | Full account: addresses, order history, stored cards (Braintree vaults), ability to place orders |
| Lifetime | Long-lived until revoked | Minutes to a browser session; bot cookies ~30 min (`__cf_bm`); re-login needed often, possibly mid-quote |
| 2FA | Bypassed by design (key issued after 2FA) | Session minted after 2FA; re-login may need 2FA and CAPTCHA every time |
| Revocation | Revoke one key without changing password | Usually only by logging out everywhere or changing password; user may not know a copy exists on another machine |
| Bot protection | API hosts are typically exempt | Device- and IP-bound clearance cookies (Cloudflare docs) fail across machines |
| Maintainability | One plugin per spec | Per-service reverse engineering of GraphQL documents, CSRF and HTML; silent breakage; no test sandbox, and every order test spends money |

- For PartCAD specifically: storing a payment-capable session as a plugin parameter, and shipping it to "a container on another machine", widens exposure beyond the GrabCAD/Printables precedent. A stolen Xometry, Fictiv or SendCutSend session can place orders against a stored card or net terms.
- Safer designs within PartCAD's model: quote-only session plugins that never call order or checkout endpoints and hand the user a cart URL to finish in the browser (as the JLC skills do); short session retention with deletion after use; no remote execution for session plugins; and a clear "unsupported by the vendor; your account may be suspended" consent text at `pc login`.

### Gaps
- No documented case was found of an open-source tool for these specific manufacturing services getting users banned. The account-risk evidence is by analogy (Discord, MyQ, Bambu, LinkedIn-style terms).
- 2FA support and session lifetimes for each of the eleven services could not be verified without accounts.
- Plaid's current share of API-based versus scraped traffic was not found.

## 6. Partnership or API access on request: a better path than session scraping?

### Takeaway
Yes, for most of them. JLC (approval-based API that includes 3D printing), PCBWay (partner API by contact), Shapeways (an official OAuth API that still answers), Treatstock (partner key), Craftcloud (public API) and possibly SendCutSend (an OAuth/PKCE flow exists for its Fusion add-in) all have a sanctioned channel PartCAD could ask about. Xometry, Fictiv and Protolabs expose buyers only through PunchOut/cXML, CAD add-ins or the web. A conversation with each is the only path that removes the ToS and bot-protection problems. Weerg has no channel and tells agents to send users to its configurator.

### Cited Findings
- **JLC3DP / JLCPCB**: "All applicants should have an account at JLCPCB to access API". Applications are reviewed on "previous orders at JLCPCB, company and business situation", and "not all applications will be approved". The API includes a 3D Printing API. The page addresses "partners" with their own website developers and does not mention individuals or open-source tools — [JLCPCB API](https://jlcpcb.com/help/article/jlcpcb-online-api-available-now) (last updated 10 Nov 2026).
- **PCBWay**: a partner API with keys "arranged through a partner program rather than self-serve signup", where "Only a quotation call is documented" for PCB; 3D printing coverage is not stated — [Supergood: PCBWay](https://supergood.ai/api-report-card/pcbway). A community MCP server says "Contact PCBWay partner support to request an API Key" for `api-partner.pcbway.com` and lists PCB quote, SMT quote and order place/confirm/cancel — [pcbway-mcp-server README](https://raw.githubusercontent.com/singlebarrellabs/pcbway-mcp-server/main/README.md).
- **Xometry**: the supplier API's production access "rides on partner status, with Approved or PIP partners allowed and others returning 403", and "Buyer side quoting and ordering stay undocumented" — [Supergood: Xometry](https://supergood.ai/api-report-card/xometry). Enterprise buyers get PunchOut into Coupa, Ariba, SAP and Dynamics ("complete everything directly on Xometry—then seamlessly push the order into your existing procurement system"), through TradeCentric — [Xometry PunchOut](https://www.xometry.com/xometry-enterprise/xometry-integration-punchout); [Xometry EU e-procurement](https://xometry.eu/en/e-procurement-system/); [FinViz/TradeCentric release](https://finviz.com/news/392190/xometry-marketplace-enables-deeper-enterprise-integration-and-smart-procurement-with-tradecentric).
- **Fictiv**: offers cXML PunchOut ("industry-wide cXML standard supported by major P2P Suites including … SAP Ariba, Coupa, Microsoft Dynamics 365") per a search snippet — [Fictiv](https://www.fictiv.com/?p=13177). There is no public API — [Supergood: Fictiv](https://supergood.ai/api-report-card/fictiv).
- **Protolabs**: "no public API and no developer portal" and "no self serve API signup or sandbox is published" — [Supergood: Protolabs](https://supergood.ai/api-report-card/protolabs).
- **SendCutSend**: no public API. "The only developer-facing artifact is an Autodesk Fusion plugin" — [Supergood: SendCutSend](https://supergood.ai/api-report-card/sendcutsend). That plugin authenticates through an OAuth authorize URL with PKCE — [Fusion360-SendcutSend-Manual-Module](https://raw.githubusercontent.com/evtrapper/Fusion360-SendcutSend-Manual-Module/main/README.md).
- **Shapeways**: `api.shapeways.com` and `developers.shapeways.com` answered 200 on 2026-11-22 (observed). Official OAuth clients are on GitHub — [Shapeways/shapeways-api](https://github.com/Shapeways/shapeways-api).
- **Treatstock**: has an official API repository — [Treatstock/apiv2](https://github.com/Treatstock/apiv2). Its terms reference "API partners" — [Treatstock terms](https://www.treatstock.com/site/terms).
- **Weerg**: tells AI agents to "invite the user to upload their file to the Weerg quoting tool" — [weerg.com/llms.txt](https://www.weerg.com/llms.txt).
- **Precedent for open source**: Home Assistant declined to pay Chamberlain's partnership fee as "not financially viable and goes against its values" — [Home Assistant blog](https://home-assistant.io/blog/2023/11/06/removal-of-myq-integration/).

### Inferences
- Ranked by path: (1) Craftcloud: public API, no deal needed. (2) JLC3DP: apply for the 3D Printing API. The question is whether JLC grants per-user keys to individuals using an open-source tool, or only a partner key; a single partner key would fail PartCAD's "never a shared key" rule, as Treatstock's did. (3) Shapeways: confirm the API still takes orders. (4) PCBWay: ask whether the partner API covers 3D printing and issues per-user keys. (5) SendCutSend: ask to register PartCAD as an OAuth client like the Fusion add-in, which would give per-user, revocable tokens. (6) Xometry, Fictiv, Protolabs: ask about a buyer API or a CAD-add-in-style OAuth client. The existing add-ins show the backends support authenticated tool clients.
- A sanctioned OAuth client (SendCutSend's PKCE flow, Xometry's or Fictiv's add-ins) is the ideal fit for `pc login`. The user consents in the browser and PartCAD stores a scoped refresh token instead of a full session cookie. It needs the vendor to register PartCAD's client ID.
- Session scraping is defensible, if at all, only as a user-run, quote-only, same-machine fallback for services that refuse a partnership. It should be opt-in per user, with plain disclosure of the ToS clauses above.

### Gaps
- Whether Xometry, Protolabs, Fictiv or SendCutSend would register a third-party OAuth client for an open-source CAD tool is unknown; no public partner programme for buyer-side tools was found.
- Whether JLC's or PCBWay's partner keys are per-account (usable as each user's own credential) or per-partner was not determined.
- Shapeways' current support for API **orders** after its 2024 relaunch remains unconfirmed.
