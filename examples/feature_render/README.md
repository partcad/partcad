# //pub/examples/partcad/feature_render

PartCAD example project to demonstrate the 2D projections `pc render` writes, and how each of them is configured on its own.

`pc render` writes 2D projections of the objects a package declares, and the
`render:` section of `partcad.yaml` says which ones and with what. Every file
type is a subsection of its own, so each is configured separately: where the
file goes (`prefix`), which objects get one (`exclude`), what the projection
looks at (`viewport_origin`, `viewport_up`), and whatever else that file type
takes -- a pixel size for the raster ones, a background color and a quality
for JPEG.

A shape may re-tune any of it for itself, by declaring a `render:` section of
its own. `cylinder` below does exactly that: the package looks at a part from
a corner, and the cylinder asks to be looked at head-on instead.

`readme` is the one entry no implementation writes. PartCAD assembles this
document itself out of what the package declares and the images the other
file types leave behind, which is why the tables below show the SVGs.

The 3D and CAD files a package publishes are a different section --
`export:` -- and a different example: see `feature_export`.

A `prefix` that points at a directory expects it to be there: PartCAD writes
the file, not the path to it, unless it is asked to with `--create-dirs`.
Here `images/` already exists, because what is in it is checked in.


## Usage
```shell
pc render                 # every file type declared below
pc render -t png          # only one of them
pc render -t dxf -O ./ :outline
```
