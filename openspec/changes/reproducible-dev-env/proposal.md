## Why

This repository's commit path only works inside the dev container, but nothing in the repo says so or provides
a headless way to get there. `.git/hooks/pre-commit` is generated by `pre-commit install` with a hardcoded
`INSTALL_PYTHON=/home/vscode/miniforge3/bin/python` — a path that exists only inside the container image — so
on a host without `pre-commit` on `PATH`, `git commit` fails with `` `pre-commit` not found ``. The documented
setup (`docs/source/contributing.rst`) assumes a human driving the VS Code Dev Containers extension, which a
coding agent working in a terminal cannot use. Agents therefore either cannot commit at all, or bypass the
required gates with `--no-verify`, which the root `AGENTS.md` explicitly forbids.

A second, latent defect makes this worse: `dev-tools/pre-commit-config.yaml` declares a `behave` hook whose
entry point `.devcontainer/behave_hook.sh` does not exist in the repository. Commits only succeed today because
`devcontainer.json` sets `SKIP=behave,...`, masking the missing file. Any environment that reconstructs the
container without that exact `SKIP` value fails on a dangling script reference.

## What Changes

- Adopt the `@devcontainers/cli` (`devcontainer up` / `devcontainer exec`) as the supported headless entry
  point into the same environment VS Code users get, with `.devcontainer/devcontainer.json` remaining the
  single source of truth for image, features, mounts, `remoteEnv.SKIP`, and the `postStartCommand` that runs
  `pre-commit install`.
- Restore the missing `.devcontainer/behave_hook.sh`, mirroring the existing `pytest_hook.sh` conventions, so
  `dev-tools/pre-commit-config.yaml` is self-consistent and no hook entry points at a nonexistent file.
- Document the container-first commit and validation flow for coding agents in the root `AGENTS.md`, replacing
  the current host-oriented `poetry install` / `pytest` / `behave` instructions that silently assume the agent
  is already inside the container.
- Document the same flow for humans in `docs/source/contributing.rst` as a CLI alternative to the VS Code
  Dev Containers extension.
- Record the reproducible development environment as a first-class capability under `openspec/specs/`, so the
  requirement that commits run in a pinned, reconstructable environment is specified rather than tribal.

Not a breaking change: the VS Code Dev Containers workflow, the pinned image, and the hook configuration all
keep working exactly as they do today.

## Capabilities

### New Capabilities
- `reproducible-dev-env`: The requirement that this repository's build, test, and commit gates run in a pinned,
  reconstructable container environment; that `.devcontainer/devcontainer.json` is the single source of truth
  for that environment; that a headless (non-VS Code) entry point exists for coding agents; and that every hook
  entry point referenced by the pre-commit configuration resolves to a file that exists.

### Modified Capabilities
- `agent-instructions`: Adds requirements that agent-facing instructions direct agents to run validation and
  `git commit` inside the reproducible environment rather than on the host, and that they state the headless
  command for entering it. The existing requirement that commit instructions reference pre-commit hooks is
  strengthened from "mention that hooks exist" to "state where the hooks can actually pass".
- `user-documentation`: Adds a requirement that `docs/source/contributing.rst` documents the CLI-based
  container entry point alongside the existing VS Code Dev Containers path.

## Impact

- **New file**: `.devcontainer/behave_hook.sh` (restores the entry point referenced by the `behave` hook).
- **Modified**: `AGENTS.md` (root) — container-first setup, validation, and commit flow.
- **Modified**: `docs/source/contributing.rst` — headless dev container CLI section.
- **New specs**: `openspec/specs/reproducible-dev-env/spec.md`; deltas to `agent-instructions` and
  `user-documentation`.
- **Unchanged**: `.devcontainer/devcontainer.json`, `dev-tools/pre-commit-config.yaml`, and the pinned image
  `ghcr.io/partcad/partcad-devcontainer:0.7.146` — this change documents and completes the existing setup
  rather than redesigning it.
- **New tooling dependency**: `@devcontainers/cli`, invoked via `npx` (Node 20 / npm 10 already present in the
  documented environment). No addition to `pyproject.toml` or `poetry.lock`.
- **Validation**: the change is proven by using the resulting flow to commit the currently staged work, with
  hooks running and passing rather than being skipped with `--no-verify`.
